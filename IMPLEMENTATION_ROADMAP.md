### Step 1: Security Hardening & Vault Isolation
- **Why**: Remove wildcard `'*'` origin vulnerability in default vault and ensure bulletproof origin boundaries.
- **Files Affected**: `veil-extension/core/secret-vault.js`, `veil-extension/benchmark/run-security-test.js`
- **Dependencies**: None
- **Expected Output**: Strict domain whitelisting for all vault credentials; updated security tests that verify cross-origin refusal.
- **Acceptance Criteria**: `resolveSecret('LOCAL_SECRET_01', 'attacker.com', 'card_number')` returns `ok: false, reason: "domain-scope-violation"`.
- **Test Required**: `node benchmark/run-security-test.js` passes with 100% strict assertions.

---

### Step 2: Benchmark Integrity & Real Measurement Instrumentation
- **Why**: Eliminate synthetic/hardcoded latency additions and RAM strings in ablation tests and scorecard UIs.
- **Files Affected**: `veil-extension/benchmark/run-ablation-study.js`, `veil-extension/benchmark/run-all-tests.js`, `veil-extension/proof/proof.js`
- **Dependencies**: Step 1
- **Expected Output**: Ablation study measures real `process.memoryUsage()` heap usage and true execution timings; `proof.js` executes actual test suite logic via messaging rather than animated `setTimeout` loops.
- **Acceptance Criteria**: Running `npm test` completes all 5 suites cleanly without synthetic delays.
- **Test Required**: `npm test` executes cleanly in <3 seconds.

---

### Step 3: Live Interactive Pipeline in Lab Studio
- **Why**: Convert the static simulated `lab.html` into a live evaluation harness that inspects the actual browser tab.
- **Files Affected**: `veil-extension/lab/lab.js`, `veil-extension/lab/lab.html`
- **Dependencies**: Step 2
- **Expected Output**: Clicking "Execute Pipeline" in Live Lab queries the active tab via `chrome.tabs.sendMessage('VEIL_RUN_TASK')`, retrieves live detections, displays the real sanitized skeleton, and executes real action resolution.
- **Acceptance Criteria**: Lab displays live telemetry originating from the active tab.
- **Test Required**: Interactive manual verification on `http://127.0.0.1:3000/veil-store.html`.

---

### Step 4: Real Local OCR & WebAssembly Perception Engine
- **Why**: Satisfy the 25% Visual Context Accuracy criterion by extracting and redacting text inside `<canvas>`, `<img>`, and PDF elements without network dependencies.
- **Files Affected**: `veil-extension/content/vision-fallback.js`, `veil-extension/vendor/`, `veil-extension/manifest.json`
- **Dependencies**: Step 3
- **Expected Output**: Lightweight Tesseract.js WASM / PaddleOCR ONNX engine bundled locally; detects PII text rendered inside canvas and images.
- **Acceptance Criteria**: Canvas PII in `test-pages/case-008-canvas-pii.html` is detected and masked without internet access.
- **Test Required**: `node real-lab/run-all.js` detects canvas PII in Case 008.

---

### Step 5: Live Ollama Multimodal VLM Integration & Verification
- **Why**: Validate the full end-to-end loop with real open-weight VLM models (`qwen2-vl:7b`, `llama3.2-vision`) running on local GPU.
- **Files Affected**: `veil-extension/server/vlm_client.py`, `veil-extension/server/app.py`, `scripts/start-all.ps1`
- **Dependencies**: Step 4
- **Expected Output**: Automatic fallback: If Ollama is running (`localhost:11434`), use `OllamaVLMClient`; if unavailable, seamlessly fall back to `MockVLMClient` with clear telemetry indicators.
- **Acceptance Criteria**: Server responds with valid JSON actions generated by Ollama in <500ms on RTX 4060.
- **Test Required**: `python -m pytest veil-extension/server` or TestClient integration suite.

---

### Step 6: Interactive Action Confirmation Modal (HIGH_RISK Gating)
- **Why**: Provide human-in-the-loop safety for destructive or financial operations (e.g. "Place Order ₹4,999").
- **Files Affected**: `veil-extension/content/inspector-overlay.js`, `veil-extension/core/action-executor.js`, `veil-extension/core/agent-orchestrator.js`
- **Dependencies**: Step 5
- **Expected Output**: When `classifyActionRisk()` flags `HIGH_RISK`, the orchestrator pauses state in `WAITING_CONFIRMATION` and renders an in-page modal. Clicking "Authorize" resumes execution; "Deny" aborts cleanly.
- **Acceptance Criteria**: High-risk actions cannot execute without explicit user button click.
- **Test Required**: End-to-end test on `case-004-netbanking.html` transfer action.

---

### Step 7: Shadow DOM & Cross-Frame Traversal
- **Why**: Ensure perception and redaction work across modern web component architectures and nested payment frames.
- **Files Affected**: `veil-extension/core/context-builder.js`, `veil-extension/core/detector.js`, `veil-extension/manifest.json`
- **Dependencies**: Step 6
- **Expected Output**: Recursive shadow root inspection; `all_frames: true` in `manifest.json`.
- **Acceptance Criteria**: Inputs inside `#shadow-root` and child iframes are perceived and redacted.
- **Test Required**: Test on synthetic Shadow DOM fixture.

---

### Step 8: Final Rehearsal & SIH Demo Lock
- **Why**: Lock in rock-solid 5-minute presentation script and verifiable metrics for ISRO evaluators.
- **Files Affected**: `docs/VEIL_MASTER_PLAN.md`, `README.md`
- **Dependencies**: Steps 1-7
- **Expected Output**: Rehearsed demo flow: 1) Side-by-side privacy proof, 2) Live checkout with ValueRef vault, 3) Adversarial attack demonstration, 4) Real benchmark scorecard.
- **Acceptance Criteria**: 100% flawless execution in live browser environment.
